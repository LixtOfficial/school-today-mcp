# School-Today Local MCP Server (v2.0)

Локальний сервер **Model Context Protocol (MCP)** для швидкої, безпечної та токено-ефективної взаємодії ШІ-агентів із системою електронного журналу **School-Today**.

Замість повільного і дорогого Computer Use (скріншотів і кліків), сервер працює напряму через захищені HTTP-запити з автоматичною підтримкою сесії та **двоетапним захистом запису (Preview → Confirm)**.

---

## 🏗️ Архітектура безпеки: Getters vs Two-Phase Setters

Усі 16 інструментів MCP-сервера чітко поділені на дві категорії:

### 🟢 1. GETTERS (Read-Only, `readOnlyHint: true`) — 10 інструментів
Виконуються ШІ-агентом **миттєво і без додаткових запитів на підтвердження**, оскільки вони лише зчитують дані та рахують аналітику, не змінюючи журнал:

| Інструмент | Призначення та типові сценарії вчителя |
| :--- | :--- |
| `get_auth_status` | Перевірка активності сесії, конфігурації автоматичного входу (`.env`) та базових даних акаунта. |
| `get_teacher_profile` | ПІБ вчителя, `teacherId`, поточний `schoolPeriodId`, зведення закріплених класів і предметів. |
| `get_classes_and_subjects` | Повний динамічний довідник усіх журналів (класи, предмети, внутрішні ID — без жодного хардкоду). |
| `get_schedule` | Розклад уроків на будь-яку дату чи період (`"сьогодні"`, `"завтра"`, `"цей тиждень"`, `"наступний тиждень"`, `"у середу"`, `"19.10"`, `start_date`..`end_date`) разом із темами та статусом ДЗ/відвідуваності. |
| `audit_lessons_filling` | **Глобальний аудит «хвостів» одним викликом:** перевіряє всі журнали вчителя за вказаний період і знаходить проведені уроки, де не заповнена тема, ДЗ або відвідуваність, із розрахунком `%` заповнення. |
| `get_class_journal` | Токено-ефективна таблиця журналу класу, стовпчики дат і типів уроків, аналітика класу (відмінники, учні в зоні ризику, кому бракує оцінок `< 3`) або картка окремого учня. |
| `get_student_dossier` | **Мультипредметне досьє учня:** за один виклик збирає повну історію оцінок, середніх балів та пропусків «Н» учня одразу з **усіх предметів**, які викладає вчитель у цьому класі (наприклад, Біологія + Хімія). |
| `get_lesson_plan` | Повне календарне планування уроків на семестр (номери уроків, дати, час, теми, домашні завдання). |
| `find_lessons` | Гнучкий пошук уроків за датою, діапазоном дат (`date_from`..`date_to`), `only_past: true`, ключовим словом (`query`) або статусом (`missing_topic`, `missing_homework`, `unfilled`). |
| `get_thematic_evaluation` | **Розрахунок тематичних оцінок:** показує поточні оцінки кожного учня, офіційну `Середньозважену` оцінку School-Today, рекомендований тематичний бал та учнів, яких ще треба опитати (`< 3` оцінок). |

---

### 🟠 2. SETTERS (Двоетапний запис, `destructiveHint: true`) — 6 інструментів
Жоден Setter фізично не може внести зміни в журнал на першому кроці (навіть якщо ШІ помилково передасть `confirm: true` без попереднього прев'ю — сервер автоматично заблокує запис і поверне Preview):

1. **Етап 1 (Preview / Аналіз):** ШІ викликає Setter. Сервер зчитує поточні дані з журналу, формує таблицю порівняння **«БУЛО → СТАНЕ»**, перевіряє ризики (наприклад, перезапис існуючої оцінки чи «Н») і видає унікальний `preview_token`.
2. **Етап 2 (Підтвердження або Правки):**
   - Якщо вчитель просить внести правки — агент формує оновлений Preview.
   - Коли вчитель підтверджує дію — агент викликає `confirm_pending_action({ preview_token })` (або повторно викликає Setter із `confirm: true` та `preview_token`), після чого сервер зберігає дані й виконує перевірочне читання (**Post-Write Verification**).

| Інструмент | Призначення |
| :--- | :--- |
| `update_lesson_content` | Заповнення або оновлення теми уроку, домашнього завдання, приміток, посилання на відеоурок (`video_link`) та дедлайну ДЗ. |
| `batch_update_lessons` | Пакетне заповнення тем та ДЗ на тиждень/місяць наперед за один виклик. |
| `set_lesson_marks` | Виставлення, зміна або **видалення** (`mark: null` / `clear: true`) оцінок (1–12) разом із **коментарями** до оцінок. |
| `batch_set_marks` | Пакетне виставлення оцінок за кілька уроків або дат. |
| `set_attendance` | Відмітка відсутніх («Н»), присутніх (`mark_all_present: true` без затирання числових оцінок!) та запізнень у хвилинах (`lateness_minutes`). |
| `confirm_pending_action` | Миттєве підтвердження та збереження підготовленого Preview за його `preview_token`. |

## 🔐 Автоматична авторизація та сесія

Сервер підтримує **автоматичний фоновий вхід** та **Sliding Cookie Persistence** (автоматично зберігає оновлені заголовки `Set-Cookie` від сервера у `cookies.json`).

Налаштуйте файл `.env` у корені проєкту (він доданий у `.gitignore`):
```env
SCHOOL_TODAY_EMAIL=your_email@gmail.com
SCHOOL_TODAY_PASSWORD=your_password
SCHOOL_TODAY_BASE_URL=https://school-today.com
```
Якщо сесія коли-небудь закінчиться, клієнт автоматично за 0.4 секунди переавторизується у фоні й виконає запит без жодної помилки.

npm run auth
