## Чому це працює

Кожен веб-додаток (включно з School-Today) спілкується з сервером через **HTTP-запити** — це, по суті, неофіційний API. Коли ви натискаєте кнопку "Зберегти оцінку", браузер відправляє POST-запит з JSON/form-data на конкретний endpoint. Ці запити можна перехопити, зрозуміти їх структуру і відтворити програмно.

## Архітектура рішення

```
┌──────────────┐     MCP Protocol      ┌──────────────────┐     HTTP Requests     ┌──────────────┐
│   AI Agent   │ ◄──────────────────► │  MCP Server      │ ◄──────────────────► │ School-Today │
│  (Claude,    │    tools/resources     │  (Node.js)       │    cookies/sessions   │   Backend    │
│   Gemini)    │                        │                  │                        │              │
└──────────────┘                        └──────────────────┘                        └──────────────┘
```

## Покрокова стратегія

### 1. Reverse Engineering HTTP API
- Відкрити School-Today в браузері → **DevTools → Network tab**
- Виконати типові дії (логін, виставлення оцінок, відмітка відвідуваності)
- Записати всі HTTP-запити: URL, method, headers, body, cookies
- Зрозуміти структуру відповідей

### 2. Побудова MCP Server
На основі перехоплених запитів створити MCP-сервер з інструментами типу:

| Tool | Опис |
|------|------|
| `login` | Автентифікація, збереження сесії |
| `get_classes` | Список класів вчителя |
| `get_students` | Учні конкретного класу |
| `get_schedule` | Розклад на день/тиждень |
| `set_grade` | Виставити оцінку |
| `set_attendance` | Відмітити відвідуваність |
| `get_grades` | Переглянути оцінки |
| `add_homework` | Додати домашнє завдання |

### 3. Переваги над Computer Use

| | MCP Server | Computer Use |
|---|---|---|
| **Швидкість** | ~100мс на дію | 5-15с на дію |
| **Токени** | Мінімальні (JSON) | Величезні (screenshots) |
| **Надійність** | Детерміновано | Може промахнутися по кнопці |
| **Вартість** | ~$0.001 за операцію | ~$0.10-0.50 за операцію |

## Основні виклики

1. **Автентифікація** — може бути CAPTCHA, 2FA, CSRF-токени. Найчастіше це вирішується через збереження cookie-сесії після ручного логіну
2. **Нестабільність** — неофіційний API може змінитись при оновленні School-Today
3. **Структура запитів** — може бути нетривіальною (вкладені форми, спеціальні заголовки)

## Наступні кроки

Хочеш, щоб ми почали з практичної частини? Для цього потрібно:

1. **Перехопити реальні HTTP-запити** — відкрий School-Today в Chrome, зайди в DevTools → Network, виконай кілька типових дій і збережи запити (можна через "Copy as cURL" або експортувати як HAR-файл)
2. На основі цього я створю **повноцінний MCP-сервер на Node.js**, який можна буде підключити до будь-якого AI-агента

Підхід з MCP — це на порядки ефективніше за Computer Use, і саме так працюють всі серйозні інтеграції з системами, що не мають офіційного API.

### Асистент:
Ось точна технічна причина, чому внутрішній браузер завис на `open_browser_url: action timed out`:

1. **Конфлікт процесів Chrome:**
   У вас у системі в цей момент уже був відкритий ваш звичайний **Google Chrome** (робочі вкладки). 
   В операційній системі Windows архітектура Chrome влаштована так: якщо один екземпляр Chrome уже працює, будь-яка спроба запустити ще один Chrome автоматично перенаправляється в існуючий процес.
2. **Блокування порту налагодження (CDP):**
   Внутрішній агент Antigravity вимагає спеціального порту керування (`--remote-debugging-port=9222`). Оскільки ваш основний Chrome був запущений раніше без цього порту, новий інстанс не зміг відкрити свій порт керування, і внутрішній агент під час спроби навігації не дочекався відповіді від браузера й завис по таймауту.

*(Згідно з інструкцією середовища: якщо інструмент `open_browser_url` видає помилку таймауту — це системний конфлікт браузера, і я маю узгодити з вами, як краще діяти далі).*

### Як тепер побудувати швидкий локальний MCP для School Today?

Оскільки структура системи повністю зрозуміла, ось як виглядатиме ваш локальний MCP-сервер:

1. **Збережена сесія:** 
   Браузер зберіг вашу авторизацію у локальному профілі. MCP-сервер може просто використовувати збережені сесійні куки або підключатися до цієї сесії.
2. **Інструменти (Tools), які отримає ШІ:**
   * `get_my_schedule()` — отримати розклад уроків на сьогодні чи будь-який день (клас, час, предмет).
   * `get_classes_and_subjects()` — отримати список ваших класів із внутрішніми ID.
   * `get_class_journal(class_name, subject)` — отримати поточні оцінки та список учнів.
   * `get_lesson_topics(class_name, subject)` — отримати календарний план уроків.
   * `set_lesson_topic_and_homework(...)` — записати тему уроку та ДЗ (з підтвердженням).
   * `set_marks(class_name, date, marks_dict)` — виставити оцінки (з обов'язковим попереднім переглядом `dry_run` для безпеки).

**Витрата токенів:** лише 150–300 токенів на запит. Жодного комп'ютерного зору!

### Що тепер реалізовано:

#### 1. Розумний автопошук уроку (Universal Lesson Resolver)
Тепер вам і ШІ **не потрібно знати жодних внутрішніх ID**. Всі ключові інструменти навчилися самостійно знаходити потрібний урок за природними параметрами:

* `subject_or_id`: наприклад `"Біологія"`
* `date`: наприклад `"05.10"`, `"05.10.2026"` або `"2026-10-05"`
* `lesson_number`: номер уроку на цю дату (наприклад `1` або `2`, якщо в розкладі стоїть пара — два уроки поспіль в один день).

Система за лічені мілісекунди сама знаходить у базі відповідний урок і виконує операцію.

#### 2. Новий інструмент: `find_lessons`
Спеціальний інструмент швидкого пошуку уроків.
* **Приклад запиту:** *«Які уроки у 7 класу з біології на 05.10?»*
* **Результат:** миттєво повертає номери уроків, точний час (`12:55 - 13:40`, `14:00 - 14:45`), поточні теми, ДЗ та їхні ID.

#### 3. Пакетні операції: `batch_update_lessons` та `batch_set_marks`
Якщо ви просите: *«Заповни теми та ДЗ для 7 класу з біології на цей тиждень на обидва уроки»* або *«Постав оцінки за кілька днів»*:
* Більше немає потреби викликати інструмент по одному разу для кожного уроку.
* Один запит передає масив уроків і оновлює все пакетно за один підхід.

#### 4. Зв'язування стовпчиків журналу з уроками в `get_class_journal`
Тепер при читанні журналу `get_class_journal` кожен стовпчик дати в таблиці повертається з прив'язкою до теми та точного `lessonId`. ШІ відразу бачить повну картину сітки журналу без додаткових запитів.

#### 5. Очищення тексту ДЗ
Раніше в поле ДЗ потрапляли службові кнопки інтерфейсу School-Today (бейджі зданих робіт `0/17 ✔️0`). Тепер функція `cleanHomeworkText` автоматично відфільтровує службові мітки платформи, залишаючи лише чистий текст домашнього завдання.
