# 📦 Проєктний Hand-Off: School-Today Local MCP Server (v2.0)

Цей документ призначений для швидкого та безшовного перенесення проєкту **School-Today MCP Server** на новий комп'ютер або в нову сесію ШІ-агента (Antigravity / Claude Desktop / Cursor).

---

## 1. Контекст та головна мета проєкту

**School-Today (`https://school-today.com`)** — веб-система електронного шкільного журналу (побудована на ASP.NET Core MVC), яка не має відкритого публічного API чи офіційного MCP.
Використання *Computer Use* (скріншоти + кліки в браузері) є повільним (15–30 сек на дію), дорогим по токенах і ненадійним.

**Рішення (MCP v2.0):**
Локальний Node.js MCP-сервер, який спілкується з бекендом `school-today.com` напряму через HTTP-запити (`axios` + `cheerio`), автоматично підтримує авторизацію у фоні та надає ШІ-агенту **16 спеціалізованих інструментів**, поділених на:
- **🟢 10 Getters (Read-Only, `readOnlyHint: true`)** — виконуються миттєво (0.2–0.5 сек) без додаткових підтверджень користувача.
- **🟠 6 Setters (Two-Phase Commit, `destructiveHint: true`)** — працюють виключно у два етапи:
  1. **Етап 1 (Preview):** Сервер зчитує поточні дані з журналу, формує таблицю порівняння `БУЛО -> СТАНЕ`, попереджає про ризики (перезапис оцінки чи `'Н'`) і генерує `preview_token`. Навіть якщо агент помилково передасть `confirm: true` на першому кроці без попереднього прев'ю, сервер заблокує запис і поверне Preview.
  2. **Етап 2 (Commit):** Тільки після явного підтвердження вчителем агент викликає `confirm_pending_action({ preview_token })` (або повторно викликає Setter із `confirm: true` та `preview_token`), після чого сервер виконує запис і робить перевірочне читання (**Post-Write Verification**).

> **⚠️ КРИТИЧНЕ ПРАВИЛО БЕЗПЕКИ:**
> Цей сервер підключений до **реального робочого журналу реальної школи** (вчитель: Патока Владислава, предмети: Біологія, Біологія і екологія, Хімія, 7–11 класи).
> **Ніколи не виконуйте реальних `POST`-записів (`confirm: true` / `confirm_pending_action`) під час тестів без прямого доручення користувача!** Для перевірки працездатності використовуйте виключно Getters або Setters у режимі `confirm: false` (`npm test`).

## 2. Покрокова інструкція перенесення на новий ПК

### Крок 1. Скопіюйте папку проєкту
Перенесіть папку `school-today-mcp-test` на новий ПК.
Переконайтеся, що на новому ПК встановлено **Node.js (v18+ або v20/22/24)**.

Якщо переносите без папки `node_modules`, виконайте в терміналі:
```bash
npm install
```

### Крок 2. Перевірте файл `.env` у корені проєкту
Файл `.env` не потрапляє в Git (він у `.gitignore`), тому при перенесенні через Git створить його вручну в корені проєкту (або скопіюйте разом із папкою):
```env
SCHOOL_TODAY_EMAIL=<ваш_email>
SCHOOL_TODAY_PASSWORD=<ваш_пароль>
SCHOOL_TODAY_BASE_URL=https://school-today.com
```
*(Додатково можна встановити `SCHOOL_TODAY_READ_ONLY=true`, якщо потрібно на рівні HTTP-клієнта заблокувати будь-які `POST`-запити).*

### Крок 3. Підключіть MCP-сервер у налаштуваннях Antigravity на новому ПК
Додайте сервер у конфігурацію MCP (`mcp_config.json` / налаштування MCP в Antigravity), вказавши **актуальний шлях до `server.js` на новому ПК**:
```json
{
  "mcpServers": {
    "school-today": {
      "command": "node",
      "args": [
        "C:/шлях/на/новому/ПК/school-today-mcp-test/server.js"
      ]
    }
  }
}
```

### Крок 4. Перевірте працездатність
Виконайте в терміналі:
```bash
npm test
```
Ця команда запустить `test_client.js`, перевірить автоматичну авторизацію, усі Getters та захист Setters у безпечному режимі `PREVIEW_ONLY`.

## 3. Структура проєкту (`src/`)

```text
school-today-mcp-test/
├── .env                       # Облікові дані для автоматичного фонового входу (в .gitignore)
├── cookies.json               # Автоматично оновлюваний Cookie Jar (в .gitignore)
├── .preview_cache.json        # Тимчасовий кеш токенів Preview (в .gitignore)
├── server.js                  # Точка входу для MCP-клієнта
├── test_client.js             # Повний набір безпечних інтеграційних E2E-тестів (npm test)
├── test_session.js            # Скрипт примусового оновлення сесії (npm run auth)
├── README.md                  # Документація користувача
├── handoff/
│   ├── HANDOFF.md             # Цей документ для швидкого онбордингу на новому ПК
│   └── chat_history_v2.md     # Очищена історія розробки, аудиту та тестування v2.0
└── src/
    ├── server.js              # Ініціалізація MCP Server (StdioServerTransport)
    ├── tools.js               # Схеми 16 інструментів (Getters & Setters) та диспетчер викликів
    ├── metadata.js            # Динамічний парсер профілю вчителя, класів, предметів і семестрів
    ├── client.js              # Реекспорт SchoolTodayClient для зворотної сумісності
    ├── core/
    │   ├── env.js             # Тихий парсер .env (0 виводу в stdout, щоб не ламати JSON-RPC!)
    │   ├── client.js          # HTTP-клієнт: Auto-Login, Set-Cookie persistence, Timeouts (15s), Retries
    │   ├── cache.js           # In-Memory TTL-кеш із префіксною інвалідацією після запису
    │   ├── normalizer.js      # Морфологія укр. днів тижня, розумні дати ("сьогодні", "завтра"), Levenshtein-пошук учнів
    │   ├── form-utils.js      # Ізольований серіалізатор ASP.NET Core <form> + перевірка помилок валідації
    │   └── preview-store.js   # Двофазний менеджер Preview-токенів (пам'ять + диск)
    └── scrapers/
        ├── schedule.js        # Розклад на будь-який тиждень/дату + Глобальний аудит заповнення уроків
        ├── journal.js         # Сітка журналу класу, аналітика, картка учня + Мультипредметне досьє
        ├── lesson.js          # Календарний план, пошук уроків, оновлення тем/ДЗ/дедлайнів + батчі
        └── grading.js         # Виставлення/очищення оцінок і коментарів, відвідуваність, запізнення, тематичні оцінки
```

## 4. Важливі технічні деталі «під капотом» School-Today (для майбутньої розробки)

Під час реверс-інжинірингу та аудиту платформи `school-today.com` було виявлено низку критичних особливостей, які вже враховані в коді v2.0:

1. **Заборона будь-якого виводу в `stdout` (`console.log`):**
   - MCP-сервер працює через `stdio`. Стандартний пакет `dotenv` у нових версіях виводить `◇ injected env from .env` у `stdout`, що ламає JSON-RPC парсер MCP-клієнта. Саме тому використовується власний тихий завантажувач `src/core/env.js`.
2. **Авторизація та Sliding Expiration (`src/core/client.js`):**
   - Кука `.AspNetCore.Identity.Application` живе 7 днів і оновлюється сервером через заголовок `Set-Cookie`. Наш клієнт перехоплює `Set-Cookie` у кожній відповіді та зберігає у `cookies.json`.
   - При протуханні куки клієнт робить `GET /Account/Login` (забирає куку `.AspNetCore.Antiforgery.*` і приховане поле `__RequestVerificationToken`) та відправляє `POST /Account/Login` (`Step=Login`, `Email`, `Password`, `RememberMe=true`), отримуючи нову сесію за ~0.4 сек.
3. **Динамічне визначення `TeacherID` за 1 запит (`src/metadata.js`):**
   - Запит `GET /Cabinet/Teachers` автоматично виконує `302 Redirect` на `/Cabinet/Teacher/{teacherId}` (наприклад, `/Cabinet/Teacher/20733`). Це дозволяє за один запит отримати і `teacherId`, і весь список журналів без жодного хардкоду.
4. **Два різних механізми редагування уроку vs журналу:**
   - **Контент уроку та запізнення (`/Timetable/LessonEdit?lessonID=...&lessonType=1` -> `POST /Timetable/ClassLessonEdit`):**
     - Відповідає за `Topic` (тема), `Notes` (примітки), `VideoConferenceLink`, `HomeworkDeadline` (обов'язково разом із чекбоксом `IsHomeworkDeadline=true`), індивідуальні ДЗ учнів `LessonPupils[i].Homework` та хвилини запізнення `LessonPupils[i].LatenessTime`.
     - ⚠️ Виставлення оцінок (`LessonPupils[i].Point`) у цій формі **не відображається** в основній таблиці журналу класу!
   - **Сітка оцінок та «Н»-ок журналу (`/Diary/DiaryEdit?timetableid=...` -> `POST /Diary/DiaryEdit`):**
     - Модальне вікно стовпчика дати в журналі. Саме воно записує оцінки (`1–12`) та позначки відсутності (`'Н'`) у головну таблицю журналу (`/Diary/DiaryView`).
     - Поля для кожного учня `i` та колонки `c` (за замовчуванням `c = 0`):
       - `Rows[i].PupilID`
       - `Rows[i].Cells[c].ID` (ID запису в БД або `0`)
       - `Rows[i].Cells[c].Mark` (значення оцінки `'1'..'12'`, `'Н'`, або `''` для видалення/очищення оцінки)
       - `Rows[i].Cells[c].Comment` (коментар до оцінки)
       - `Rows[i].Cells[c].MarkTypeValueID` (завжди `'0'` для 12-бальної шкали)
5. **Розклад на будь-яку дату та Глобальний аудит (`/ClassDetail/TeacherTimetableInfo`):**
   - Віджет у кабінеті вчителя показує лише поточний тиждень. Натомість сторінка `/ClassDetail/TeacherTimetableInfo?StartDate=YYYY-MM-DD&EndDate=YYYY-MM-DD` за один запит повертає розклад по **всіх класах і предметах** на будь-який тиждень чи місяць (включно з майбутніми тижнями!) разом із темами та прапорцями `Так`/`Ні` для ДЗ і відвідуваності.
6. **Тематичні оцінки (`/Diary/ThematicDiaryEdit`):**
   - Ендпоінт `/Diary/ThematicDiaryEdit?periodid=...&timetableid=...&classid=...&disciplineid=...&teacherid=...` повертає офіційно розраховану сервером `Середньозважену` оцінку для кожного учня (`Rows[i].Cells[1].Mark`), яку використовує наш інструмент `get_thematic_evaluation`.
